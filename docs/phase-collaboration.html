read / write

读写边界：契约库不是所有人的工作区

manager 维护契约；worker 只拿到任务包和允许写的路径；用户通过门禁做决定；维护者在另一条旁路上处理工具改进。

正常读写路径 归档 / 受限路径 maintainer 旁路
A

共享真相

PROJECT-PLAN、ROADMAP、REQUIREMENTS、ARCHITECTURE、SPEC。manager 写；worker 只通过任务包读取。

B

当前版本工作集

当前阶段的 TASK、VR、BUG、RELEASE。manager 写；worker 只写自己的任务包与 allowed_paths。

C

冷归档

版本关闭后迁入 archive/R{n}。默认不读；查询必须带 reason，并写 READ-LOG。

D

热状态

current.json 只存指针、计数和下一动作，必须 ≤ 8KB；可从任务、路标和 ledger 重建。

E

审计日志

ledger 记录状态变迁；READ-LOG 只记谁、何时、读了什么、为什么、多少字节，不记内容。

operating rules

四条不能越过的线

上下文边界

worker 的上下文 = task packet + 自己的任务 bundle + allowed_paths。不是整个契约库，也不是别人的任务；CLI 角色守卫与 PreToolUse hook 拦截越权命令/直接读写，submit 用 diff + 快照校验路径。

评审独立性

低风险由 manager review；中/高风险由 worker2 独立评审；critical 需要用户参与验收。high/critical 不能降级为 manager 自审；accept 读取 review 文件结论。

发布边界

release freeze 需要 P5 已退出且用户批准；只生成冻结清单，published: false。冻结不等于发布；发布需要用户批准和显式授权。

状态可重建

current.json 是派生状态；缺失或损坏时从 ROADMAP、任务卡与 ledger 重建。state 超过 8KB 直接报错，不静默写回。
