## 目标

读取整合后的逻辑用例列表，根据方法选择规则为每个逻辑用例推荐最适合的测试设计方法，
生成设计计划表并与用户确认。确认后的计划用于指导后续的并行用例设计。

## 适用范围

- 适用阶段：MFQ 分析的 plan 阶段
- 输入：`.mfq-work/integration/logic-cases.md`
- 输出：`.mfq-work/integration/design-plan.md`

## 前置条件

- [ ] 测试点整合完成（`.mfq-work/integration/logic-cases.md` 存在）
- [ ] 测试数据已分配（`.mfq-work/integration/test-data.md` 存在）

## 方法选择规则（CF-04）

| 条件 | 推荐方法 | 识别特征 |
|------|---------|---------|
| 简单输入/输出，关注数据有效性 | **数据组合法** | 参数多、取值有限、无复杂流程 |
| 业务处理流程，存在分支判断 | **流程图法** | 有 if/else 分支、多步骤顺序处理 |
| 状态变迁，对象有生命周期 | **状态图法** | 对象有多种状态、事件触发状态转换 |
| 极简场景，步骤和数据都单一 | **直接设计法** | 仅在确实无法套用上述方法时使用，应极少 |

### 详细判定流程

```
逻辑用例 → 分析测试逻辑特征
    │
    ├── 是否存在状态变迁？ ──Yes──→ 状态图法
    │
    ├── 是否存在流程分支？ ──Yes──→ 流程图法
    │
    ├── 是否有多个参数需组合？ ──Yes──→ 数据组合法
    │
    └── 步骤和数据都极简？ ──Yes──→ 直接设计法（需标注理由）
```

## 执行流程

### 步骤 1：逐条分析

读取 `logic-cases.md` 中的每个逻辑用例，分析其测试逻辑特征：

- 涉及的输入参数数量和取值范围
- 处理步骤是否包含分支判断
- 测试对象是否有状态变迁
- 测试数据的复杂度

### 步骤 2：方法推荐

按判定流程为每个逻辑用例推荐设计方法，输出设计计划表：

```markdown
## 设计计划表

| LC-ID | 逻辑用例标题 | 推荐方法 | 推荐理由 | 参数数 | 有分支 | 有状态 |
|-------|------------|---------|---------|--------|--------|--------|
| LC-001 | 日志服务器配置参数验证 | 数据组合法 | 5个参数、取值有限、无流程 | 5 | 否 | 否 |
| LC-002 | 日志过滤规则处理流程 | 流程图法 | 3个分支判断点 | 2 | 是 | 否 |
| LC-003 | 日志告警状态管理 | 状态图法 | 4种状态、事件驱动转换 | — | — | 是 |
```

### 步骤 3：用户确认

将设计计划表展示给用户确认：

```
## 设计方法确认

以下为每个逻辑用例的推荐设计方法，请确认或修改：

[展示设计计划表]

您可以：
1. 全部确认
2. 修改某个逻辑用例的设计方法
3. 合并/拆分逻辑用例
```

用户确认后标记 `confirmed: true`。

### 步骤 4：输出

写入 `.mfq-work/integration/design-plan.md`：

```markdown
---
confirmed: true
confirmed_at: "2026-04-10T..."
---

# <特性名> — 测试设计计划

## 设计方法分布

| 方法 | 逻辑用例数 | 占比 |
|------|-----------|------|
| 数据组合法 | N | X% |
| 流程图法 | M | Y% |
| 状态图法 | K | Z% |
| 直接设计法 | J | W% |

## 设计计划详表

| LC-ID | 标题 | 方法 | 理由 | 模块 | 子模块 |
|-------|------|------|------|------|--------|
| LC-001 | ... | 数据组合法 | ... | ... | ... |
```

## Gotchas

- 直接设计法应尽量避免，如果推荐了直接设计法必须标注详细理由
- 同一子模块的逻辑用例可能使用不同设计方法，这是正常的
- 用户可能要求修改推荐方法，需要支持单条修改
- 设计计划确认后不应轻易变更（除非需求变更触发）

## 验收标准

- [ ] 每个逻辑用例都有推荐方法
- [ ] 推荐理由清晰且符合 CF-04 规则
- [ ] 直接设计法占比 < 10%
- [ ] 用户已确认设计计划
- [ ] 输出文件写入 `.mfq-work/integration/design-plan.md`
