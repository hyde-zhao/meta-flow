## 目标

对设计计划中标记为"数据组合法"的逻辑用例，执行四步设计过程，
从等价类划分到物理用例输出，生成完整的测试用例设计过程文档。

## 适用范围

- 适用阶段：MFQ 的 design 阶段
- 输入：`.mfq-work/integration/design-plan.md`（方法=数据组合法的 LC）
- 输出：`.mfq-work/design/<module>/<sub-module>/` 目录下的设计文件

## 前置条件

- [ ] 设计计划已确认（`design-plan.md` 中 `confirmed: true`）
- [ ] 当前逻辑用例的推荐方法为"数据组合法"

## 四步设计过程

### 第一步：等价类划分表

对逻辑用例涉及的每个测试参数/数据进行等价类划分：

```markdown
## 等价类划分表

| 测试数据 | 有效等价类 | 无效等价类 | 选取策略 | 选取结果 |
|---------|-----------|-----------|---------|---------|
| 日志服务器IP | [1] 合法IPv4 [2] 合法IPv6 | [3] 空值 [4] 非法格式 | 边界值 | 192.168.1.1, ::1, 空, abc |
| 端口号 | [5] 1~65535 | [6] 0 [7] 65536 [8] 负数 | 边界值+特殊值 | 1, 514, 65535, 0, 65536, -1 |
| 协议类型 | [9] TCP [10] UDP | [11] 非法协议名 | 遍历 | TCP, UDP, XXX |
```

**划分原则**：
- 有效等价类：正常有效的输入值范围
- 无效等价类：超出规格的无效输入
- 边界值：在等价类边界上选取（min, min+1, max-1, max, min-1, max+1）
- 特殊值：空值、null、默认值等

### 第二步：数据组合分析表

基于等价类划分，生成数据组合：

```markdown
## 数据组合分析表

| 数据项 | 取值 | 组合分析 | 约束条件 | 组合策略 | 组合结果 |
|--------|------|---------|---------|---------|---------|
| IP+端口+协议 | 见等价类 | 3×4×2=24 | 无特殊约束 | pairwise | 12组 |
```

**组合策略**：
- **全组合**：参数少（≤3 个）、取值少（≤4 个）时使用
- **Pairwise**：参数多或取值多时，使用两两组合压缩
- **正交表**：存在约束条件时参考正交实验设计
- **基于风险**：高风险组合全覆盖，低风险组合抽样

**组合爆炸检测**：
- 如果全组合数 > 50，自动建议使用 pairwise 压缩
- 如果 pairwise 后仍 > 30，建议基于风险筛选

### 第三步：逻辑用例设计

将组合结果转化为逻辑用例：

```markdown
## 逻辑用例

| LC-ID | 用例标题 | 测试数据 | 预期行为 | 覆盖TP |
|-------|---------|---------|---------|--------|
| LC-001-01 | 有效IP+有效端口配置 | IP=192.168.1.1, Port=514, Proto=UDP | 配置成功 | TP-M-001 |
| LC-001-02 | 无效IP配置验证 | IP=abc, Port=514, Proto=UDP | 提示IP格式错误 | TP-M-002 |
```

### 第四步：物理用例设计

将逻辑用例细化为可执行的物理用例：

```markdown
## 物理用例

### PC-CFG-SRV-001: 有效IP+有效端口配置日志服务器

**优先级**：P1
**测试类型**：功能
**测试数据**：IP=192.168.1.1, Port=514, Proto=UDP

**预置条件**：
1. 防火墙已正常启动
2. 管理员已登录 Web 管理界面

**测试步骤**：
| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 进入日志中心→日志服务器配置 | 显示服务器配置页面 |
| 2 | 输入 IP=192.168.1.1, 端口=514, 协议=UDP | 输入框接受输入 |
| 3 | 点击"确定" | 配置保存成功，提示"配置已生效" |
| 4 | 查看服务器列表 | 新增的服务器显示在列表中 |
```

## 优先级分配规则

| 场景 | 优先级 |
|------|--------|
| 所有有效等价类的正常组合 | P1 |
| 有效边界值 | P2 |
| 单个无效等价类 | P2 |
| 多个无效等价类组合 | P3 |
| 特殊值/极端值 | P3~P4 |

## 输出目录结构

```
.mfq-work/design/<module>/<sub-module>/
├── design-process.md     # 包含四步设计过程
└── physical-cases.md     # 物理用例列表
```

## Gotchas

- 组合数过大时，必须使用压缩策略，不要生成 50+ 物理用例
- 无效等价类通常单独测试（一次只变一个无效值），不做无效值间组合
- 有约束关系的参数（如参数 A=X 时参数 B 只能取 Y），需在约束列注明
- 保留所有测试点到物理用例的追踪关系
