## 目标

基于 feature-parser 输出的结构化需求和已确认的三~五级目录，
逐模块/子模块分析功能点，为每个功能点生成测试点，
确保所有需求和用户场景的功能被完整覆盖。

## 适用范围

- 适用阶段：MFQ 分析的 m-analysis 阶段
- 输入：`.mfq-work/feature-input/` + `.mfq-work/scenarios/`
- 输出：`.mfq-work/m-analysis/test-points.md`

## 前置条件

- [ ] `.mfq-work/feature-input/raw-requirements.md` 存在
- [ ] `.mfq-work/feature-input/directory-structure.md` 存在（用户已确认）
- [ ] `.mfq-work/scenarios/confirmed-scenarios.md` 存在（用户已确认）

## 执行流程

### 步骤 1：加载输入

1. 读取 `raw-requirements.md` 获取需求条目列表
2. 读取 `directory-structure.md` 获取目录层级
3. 读取 `confirmed-scenarios.md` 获取应用场景

### 步骤 2：逐模块功能分析

按四级目录（模块）→五级目录（子模块）的顺序，依次分析：

对每个子模块：
1. 提取该子模块关联的需求条目
2. 提取该子模块关联的应用场景
3. 分析功能点：该子模块需要实现哪些功能
4. 对每个功能点，考虑以下维度生成测试点：
   - **正常功能**：功能按预期工作
   - **参数边界**：输入参数的有效/无效边界
   - **异常处理**：错误输入、异常条件下的行为
   - **默认值**：默认配置下的行为
   - **交互影响**：与同模块内其他功能的交互

### 步骤 3：测试点标注

每个测试点必须标注以下信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| TP-ID | 测试点编号 | `TP-M-<模块缩写>-<子模块缩写>-NNN` |
| 所属模块 | 四级目录名称 | 配置管理 |
| 所属子模块 | 五级目录名称 | 日志服务器配置 |
| 测试点描述 | 具体的测试验证内容 | 验证配置最大日志服务器数量时系统行为 |
| 关联需求 | 需求编号列表 | SR-001, SR-003 |
| 关联场景 | 场景编号列表 | SCN-XXX-001 |
| 来源 | M 分析 | M-analysis |
| 测试类型建议 | 功能/边界/异常/默认 | 边界 |

### 步骤 4：覆盖初检

完成所有模块分析后，执行初步覆盖检查：

1. **需求覆盖**：检查每条 SR 至少关联 1 个测试点
2. **场景覆盖**：检查每个场景的关键功能点至少关联 1 个测试点
3. **输出未覆盖项**：如有未覆盖的需求或场景，标记为 `⚠️ 待补充`

### 步骤 5：输出

将测试点列表写入 `.mfq-work/m-analysis/test-points.md`：

```markdown
# <特性名> — M 分析测试点

## 统计

| 维度 | 数量 |
|------|------|
| 模块数 | N |
| 子模块数 | M |
| 测试点总数 | K |
| 需求覆盖率 | X/Y (Z%) |
| 场景覆盖率 | A/B (C%) |

## 模块：<四级目录名>

### 子模块：<五级目录名>

| TP-ID | 测试点描述 | 关联需求 | 关联场景 | 类型 |
|-------|-----------|---------|---------|------|
| TP-M-CFG-SRV-001 | ... | SR-001 | SCN-001 | 功能 |
| TP-M-CFG-SRV-002 | ... | SR-001 | — | 边界 |

---
（下一模块...）
```

## 测试点生成原则

1. **一个功能点至少一个测试点**：不允许功能点无测试覆盖
2. **正面优先**：先覆盖正常功能，再覆盖异常和边界
3. **粒度适中**：测试点应可独立验证，不宜过粗或过细
4. **可追溯**：每个测试点必须关联至少一条需求
5. **不预设设计方法**：M 分析只关注"测什么"，不关注"怎么测"

## Gotchas

- 需求描述中隐含的功能也需要提取测试点（如"支持 X"隐含"不支持 Y 时的行为"）
- 同一需求可能跨多个子模块，需在各相关子模块都生成测试点
- 不要在 M 分析阶段引入耦合测试点（那是 F 分析的职责）
- 不要在 M 分析阶段引入质量属性测试点（那是 Q 分析的职责）
